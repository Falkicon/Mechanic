# Reference Files

Reference files hold deep content that a SKILL.md routes to.

## Principles

1. **Self-contained**: useful on its own, with a one-line purpose at the top.
2. **Actionable**: rules, patterns, working examples; minimal background.
3. **Verified**: every API, command, flag, port and path exists in this repository (or is clearly external, such as Blizzard APIs).
4. **Single owner**: one fact lives in one file. The protocol is in `using-mechanic`; the command list is generated; link instead of copying.
5. **Sized to load**: aim for under about 250 lines; split by topic when longer.

## Structure

```markdown
# Topic

One-line purpose.

## Concept
## Patterns (with code)
## Best practices (short list)
```

Code examples for addons are **Lua 5.1** (no `goto`, `bit32`, `//`). Agent-facing tool calls use MCP style (`addon.lint(addon="X")`).

## Naming

`references/<topic>.md`, lowercase with hyphens, named for the topic, not the skill.

## Generated files

`using-mechanic/references/afd-commands.md` is generated by `.claude/gen_command_reference.py`. Never edit it by hand; edit the command (description, field descriptions) and regenerate.
